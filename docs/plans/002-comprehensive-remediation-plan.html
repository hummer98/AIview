1. 目的・範囲・前提

目的

画像・URL同一性、非同期operationの世代、window単位の状態所有を型とtransactionで保証し、同種のnavigation/state bugを個別修正し続ける構造を終わらせる。

互換性

画像・お気に入り・thumbnail disk cacheの既存形式は変更しない。recent foldersは無損失migration、telemetryは旧clientを一定期間受ける段階移行とする。

非目標

新しい画像形式、UI刷新、ライブfolder監視、App Store sandbox化、analytics項目追加は行わない。修正中のfeature追加は凍結する。

version前提: 大きな内部構造変更とtelemetry protocol v2を含むため、次のminor release v0.10.0を候補とする。ユーザー向け操作とファイル形式は後方互換なのでmajor bumpは不要。
開始条件: PR-01でunit testが「buildできる」だけでなく、CI上で1件以上実行されたことをxcresultから検証する。現在のXcode 26.6 local runner assertionを未解決のまま、中核state refactorへ進まない。

2. 拘束する設計決定

以下は実装中に再び選択肢へ戻さない。変更する場合は理由・影響・代替案をADRとして先に更新する。

D1. Window stateはscene-local

globalに残すのはsettings、recent-folder repository、telemetry coordinator等のprocess serviceだけ。folder、selection、zoom、reload、cache-clear、sibling command、window metricsは各sceneが所有する。

D2. 表示対象は1個のSelection

BrowserSelection(url, index, image, loadID)をcommit単位にする。currentImageURLを配列indexから別計算しない。削除・favorite・metadataは常にcommitted selectionのURLを使う。

D3. 非同期commitは二重token

folderを表すsessionIDと個別loadを表すoperationIDを持つ。すべてのawait後に両方を照合し、古い完了はstateへ一切commitしない。

D4. Scannerはevent sequence

3本のasync callbackと共有cancel booleanを廃止し、所有Taskとterminationを持つAsyncThrowingStream<FolderScanEvent>へ移行する。cancelはsequence終了として伝える。

D5. 非sandbox配布を維持

任意pathを開けるDeveloper ID配布を維持する。security-scoped bookmark、start/stop API、sandbox用entitlementを撤去し、recent folderは正規化pathとして保存する。

D6. ログはprivate by default

publicを許すのはcount、duration、enum、status code等だけ。path、filename、URL、error descriptionはprivate。生成AI promptは一切logしない。独自平文incident fileは撤去する。

D7. Telemetry v2はPOST + bounded retention

routine pingをJSON POSTへ移し、rate limit・入力制限・no-storeを適用する。stats keyはAuthorization header。D1は400日retentionと削除endpointを持つ。legacy GETはrate-limit付きで90日だけ残す。

D8. 最終言語modeはSwift 6

lock保護を理由に@unchecked Sendableを増やさない。同期cacheはtyped lock、UI stateはMainActor、I/O serviceはactor/owned Taskで表現し、全targetをSwift 6でbuildする。

7. テスト戦略

Pure state tests

BrowserSessionState、Selection、favorites snapshot、error mapping、diagnostic sanitization。時刻・UUID・filesystemを注入し、sleepや実I/Oへ依存しない。

Concurrency tests

controllable suspension pointを持つfake scanner/loader/storeで、A→B、cancel、late completionを決定的に再現する。固定sleepだけのrace testは禁止。

Integration / UI

実temp folder、mock Trash、2window accessibility、focused menu command、read-only cache failure。UI test fixtureはnetworkを無効化する。

Worker tests

Cloudflare推奨のWorkers Vitest integrationでD1とbindingを含める。各test fileのstorage isolationを利用し、retention testだけ明示時刻を注入する。

Static / build

Swift 6 Debug/Release、analyze、SwiftLint、SwiftFormat、ShellCheck、log privacy check、dependency lock差分を毎PRで実行する。

Runtime evidence

release candidateでInstruments Leaks/Allocations、TSan、window open-close、cache clear、100回folder切替、1,000画像navigationを測定する。

計画する共通コマンド

task ci                 # build + tests(count>0) + analyze + lint + format + shellcheck
task test:race          # deterministic session/task race suite

Cloudflare rollout

  1. Staging: local migrationsとVitest後、staging D1へmigration。v2 POST / delete / stats、legacy GETをsmoke test。
  2. Production server first: D1 exportを取得し、migrationをlist→apply。Worker deploy後、old GETとnew POST両方の204、stats auth、429、no-storeを確認。
  3. Client release: v0.10.0をPOST clientとしてrelease。server側でroute別countだけを観測し、payload/UUIDをlogしない。
  4. Retention: 初回scheduled deleteはdry-run countをlogしてから有効化。400日境界を確認する。
