Plan 001 — 前回の表示位置を復元

Status: approved（design-review B1/B2/B3 + S1–S4 反映済み）  ·  Plan ref: plan:001  ·  ADR: docs/adr/001-favorites-file-schema-v2.html  ·  Review: docs/reports/001-design-review.html

Intent & scope

フォルダ毎の .aiview/favorites.json に「最後に表示していた画像」を記録し、 次にそのフォルダを開いた時、記録があれば「前回の位置へ移動するか」を尋ねる確認ダイアログを表示する。 OK で表示位置をその画像へ移動する。記録は画像切替の都度デバウンスして書き込む。 ダイアログ表示の ON/OFF は設定で切替可能(デフォルト ON)。

スコープ外: サブディレクトリ統合モードでの記録・復元 / 「最近見た画像」複数履歴(1件のみ保持) / アプリ起動時のフォルダ自動オープン(既存のウィンドウ状態復元とは別機能)。

決定済みの仕様（ユーザー確認済み）

論点決定
記録タイミング画像切替の都度・0.8秒デバウンスで .aiview/favorites.json に書込
保存形式favorites.json を拡張(ADR 001: v2 ラッパー + 後方互換)
ダイアログ条件記録があれば常に表示(明示的にファイルを指定して開いた場合も)
頻度/設定設定トグルで ON/OFF。トグルは確認ダイアログのみを制御し、記録は常時行う(下記 注記)
設定トグルの意味の決定: トグル(前回の表示位置を確認する, 既定 ON)は 確認ダイアログの表示可否のみを制御する。記録(lastViewedImage の書込)はトグルに関係なく常時行う。 理由: 記録は .aiview への既存書込と同程度に安価で、トグルを ON にした瞬間から復元が機能するため。 この解釈で問題ないか承認時に確認してください(別案: トグル OFF で記録も止める)。

Flow — 画像移動時の記録（デバウンス）

sequenceDiagram
  participant U as ユーザー
  participant VM as ImageBrowserViewModel
  participant FS as FavoritesStore(actor)
  U->>VM: moveToNext / カルーセル選択 → jumpToIndex(i)
  VM->>VM: currentIndex=i, 画像ロード
  VM->>VM: scheduleRecordLastViewed() (前回Taskをcancel)
  Note over VM: 0.8s 待機（連打中は都度リセット）
  VM->>FS: setLastViewedImage(currentImageURL.lastPathComponent)
  FS->>FS: .aiview/favorites.json を v2 で atomic 保存
重要(競合回避) — design-review B1 反映: 「jumpToIndex を経由したか」では記録ゲートにできない。フィルタ ON/OFF(setFilterLevel 812行)、 フィルタ index 同期(handleFilteredIndexChange 855/859行)、アンカー同期(syncCurrentIndexByAnchor 1434行)も jumpToIndex を通り、これらはユーザーの「移動」ではない。よって jumpToIndex(_ index: Int, recordLastViewed: Bool = false) の明示フラグで記録を制御する。
・recordLastViewed: true を渡すのはユーザー操作のみ: moveToNext/moveToPrevious(403/406/417/420)、 moveToNextWithLoop/moveToPreviousWithLoop(1025/1053)、 カルーセルタップ(MainWindowView.swift 235行 → jumpToIndex(index, recordLastViewed: true))、復元確定。
・それ以外(フィルタ/アンカー/その他内部ジャンプ)は既定 false。
初期自動表示(handleFirstImage/handleScanComplete)は jumpToIndex 自体を経由せず currentIndex を直接設定するため当然記録されない。これにより復元プロンプトを出す前に初期画像で lastViewedImage を上書きする事故を防ぐ。

Acceptance criteria

各項目は検証可能。inspector はこれに照らして GO/NOGO を出す。
  • AC1: 通常モードで recordLastViewed: true のユーザー移動(矢印/「次へ・前へ」/ループ移動/カルーセル選択)を行うと、約0.8秒のデバウンス後に現在画像のファイル名が <folder>/.aiview/favorites.json の lastViewedImage に保存される。観測点: 保存後に FavoritesStore.getLastViewedImage() またはディスク上 JSON の lastViewedImage を直接アサート。negative: デバウンス満了前は未記録(古い値のまま)であること。お気に入りデータ(favorites)は保持される。
  • AC2: 後方互換 — 旧 {"a.jpg":3} 形式を読み込んでも favorites が失われず、保存時に v2 形式 {"favorites":{…},"lastViewedImage":…} へ移行する。病的ケース(空 {}、{"favorites":1} のようにファイル名が "favorites" の legacy)も legacy として安全に読める。既存 FavoritesE2ETests が全て green。
  • AC3: フォルダを開いた時、設定 ON かつ非統合モードかつ記録 lastViewedImage が現在フォルダに存在し、初期表示位置と異なる場合に移動確認ダイアログを表示する。観測点: viewModel.lastViewedRestorePrompt != nil かつその filename が記録値と一致。openFile/openPath/パス入力で明示的にファイルを指定して開いた場合も(記録があれば)表示する。
  • AC4: ダイアログで「移動」を選ぶと、確定時に imageURLs からファイル名で index を再解決し currentIndex がその位置へ移動・画像が更新される(同一 index ガードに阻まれない)。「このまま」を選ぶと位置は変わらない。どちらでも lastViewedRestorePrompt が nil に戻る。
  • AC5: フォルダを開いた直後の初期自動表示(先頭画像 or 明示指定画像)、およびフィルタ ON/OFF・アンカー同期等の内部ジャンプ(recordLastViewed: false)では lastViewedImage を記録しない。観測点: フォルダを開いて待機後、記録値が開く前のまま不変であることをアサート。
  • AC6: 記録画像がフォルダ内に存在しない / 記録が初期位置と同一 / サブディレクトリ統合モード / 設定 OFF の場合は lastViewedRestorePrompt == nil(ダイアログを表示しない)。
  • AC7: 設定トグル「前回の表示位置を確認する」(既定 ON)を SettingsView から切替でき、UserDefaults に永続化される。OFF にすると次回以降フォルダを開いてもダイアログは出ない(記録は継続)。
  • AC8: task build が成功し、task test:unit(既存 FavoritesE2ETests + 新規 LastViewedImageTests)が green。

実装ノート（implementer 向け要点 — design-review 反映済み）

  • FavoritesStore: struct FavoritesFile: Codable { var favorites: [String:Int]; var lastViewedImage: String? } を導入(favorites は非 optional。空は [:]。S3)。共通 loadFile(at:) -> FavoritesFile(v2 を試行 → 失敗で legacy [String:Int] → FavoritesFile(favorites:lastViewedImage:nil))を作り、loadFavorites / loadFavoritesFromDisk(nonisolated)双方で使う。 getLastViewedImage() -> String? を公開(AC 観測点。B3)。 setLastViewedImage(_ filename: String, for folderURL: URL) は対象フォルダ URL を引数で受け、actor 内で currentFolderURL と一致する時のみ書く(古いフォルダ向け遅延書込を弾く。S2)。非統合モードのみ有効。 saveToDisk() は常に v2 で書く。統合モードの saveToDisk(folderURL:favorites:) は既存ファイルの lastViewedImage を read-modify-write で保全。
  • SettingsStore: キー restoreLastViewedConfirmEnabled(Bool, 既定 true)を追加し registerDefaults に登録。
  • ViewModel: SettingsStore を注入可能プロパティで保持(既定 SettingsStore())。 private var pendingLastViewedFilename: String?、公開 var lastViewedRestorePrompt: LastViewedRestore?(struct { let filename: String } — index は持たない。B2)。 confirmRestoreLastViewed() は確定時に imageURLs.firstIndex{ $0.lastPathComponent == filename } でindex を再解決し jumpToIndex(idx, recordLastViewed: true)、その後 prompt=nil。dismissRestoreLastViewed() は prompt=nil のみ。 デバウンスは private var lastViewedRecordTask: Task<Void,Never>? + 0.8s sleep。記録対象 folderURL を Task にキャプチャ。 記録ゲートは jumpToIndex(_ index:, recordLastViewed: Bool = false) の明示フラグ(B1)。記録は recordLastViewed == true かつ非統合モードかつ非プライバシーモード(!isPrivacyMode。S4)時のみ scheduleRecordLastViewed() を呼ぶ。 openFolder は冒頭の旧処理 cancel と同じ位置で lastViewedRecordTask?.cancel()(loadFavorites より前。S2)し、prompt/pending をクリア。handleScanComplete 末尾で(設定 ON・非統合・記録あり・初期 index と相違)時に pendingLastViewedFilename から prompt をセット。 deleteCurrentImage 冒頭で lastViewedRecordTask?.cancel()(ずれた currentImageURL の遅延記録を防ぐ。S1)。
  • MainWindowView: カルーセルタップ(235行)を jumpToIndex(index, recordLastViewed: true) に変更。 viewModel.lastViewedRestorePrompt != nil を Binding<Bool> 化(errorBinding と同型)。.alert("前回の表示位置", …) で「移動」(default)→Task { await viewModel.confirmRestoreLastViewed() }、「このまま」(cancel)→viewModel.dismissRestoreLastViewed()。message にファイル名を出す。
  • SettingsView: 新規タブ(例「表示」)または既存に Toggle("フォルダを開いたとき前回の表示位置を確認する") を追加し SettingsStore.restoreLastViewedConfirmEnabled に保存。footer/help に「記録はこの設定に関わらず行われます(プライバシーモード中を除く)」と明記(S4)。

Open questions / risks

  • 設定トグルの意味(記録は常時 vs OFF で記録停止)— 上記注記。承認時に確認。
  • スライドショー自動送りも jumpToIndex 経由のため記録対象になる。意図通り(「最後に表示していた画像」)として許容。
  • 既存 FavoritesE2ETests がディスク上の JSON 形式に直接依存していないか要確認(implementer/inspector が確認)。
  • ダイアログ表示はスキャン完了後(全ソート済みリストで index を確定)。巨大フォルダではプロンプトが少し遅れて出るが、resume の性質上許容。
