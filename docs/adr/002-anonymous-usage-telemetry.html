ADR 002 — 匿名利用計測（Cloudflare Worker + D1）

Status: accepted  ·  関連: TelemetryService.swift / cloudflare/aiview-metrics/

Context

AIview は GitHub Releases（dmg/zip 直DL）と Homebrew Cask で配布しているが、 実際にどれくらいダウンロード・利用されているかを測る手段が無い。 GitHub の download_count は CI（tap 更新時の sha256 取得）や brew の zip 取得が混ざりノイズが多く、 サードパーティ tap には Homebrew の install 統計も無い。何より「DL 後に起動・継続利用されているか」は アプリがテレメトリを持たない限り原理的に分からない。

一方で AIview はローカル完結・ネットワーク非依存・プライバシー重視（プライバシーモード等）の思想を持つ。 計測のために通信を入れることは思想の変更点であり、最小限かつ透明・停止可能である必要がある。

Decision

アプリ起動時に、仮名識別子を含む利用pingをUTC日ごとに最大1回送信する。 送信先は自前ホストの Cloudflare Worker + D1（cloudflare/aiview-metrics/）。

  • opt-out（既定 ON）: 設定「表示 > プライバシー > 匿名の利用統計を送信する」で停止できる。 OFF時はin-flight ping/retryを即cancelし、OFFの間は通常pingを一切送らない。userが明示的に開始するserver deleteだけはOFF中も許可する。
  • 送信・保存する項目: stableでhigh-entropyなrandom install UUIDは匿名ではなく仮名識別子（pseudonymous identifier）である。これにアプリ版 / macOS版 / CPUアーキ（arm64・x86_64）/ localeを加える。 国コードはサーバ側で CF の cf-ipcountry ヘッダから付与（IP は保存しない）。 file path・画像・prompt・user名など個人的な内容は送らない。
  • 日次デバウンス: UserDefaults に最終送信日(UTC)を持ち、同日は再送しない。 process-global coordinatorがin-flight/retry Taskを1個だけ所有し、POST /v1/pingの2xx確認後だけ当日を記録する。transport/429/5xxは初回+2回（1秒、2秒backoff）に限定し、失敗後は次回launchへ残す。
  • サーバは install 単位 1 行のみ保持（イベントログは持たない）。 UUID、アプリ版、macOS版、CPUアーキ、locale、国code、初回/最終送信時刻、active day数を保存し、最終送信から400日を超えた行を日次削除する。
  • 削除: Settingsから旧UUIDをPOST /v1/deleteでserver削除できる。2xx後だけlocal markerを消して新UUIDを生成し、失敗時は旧UUIDを維持して再試行を提示する。delete開始時は旧pingをcancelし、終了を待ってから送る。
  • 集計は Worker の /stats（Bearer STATS_KEY header保護）が JSON で返す。

エンドポイント

ルート用途
POST /v1/pingstrict JSON bodyを検証し、install行をupsertして204
POST /v1/deletestrict JSON bodyのinstall UUIDを冪等削除して204
GET /statsAuthorization Bearer認証済み集計JSON

Consequences

  • 易: ダウンロード数のノイズに頼らず「実利用（起動）ベース」の指標が得られる。無料枠（Worker + D1）で $0。
  • 受容: ローカル完結アプリに初めて通信が入る。既定 ON のため、初回リリース時は README / 設定でその旨を明示し、opt-out を確実に提供する。
  • 注意: routine pingはbounded retry後も失敗すればmarkerを残さず、次回launchで再試行する。cancellationは障害表示しない。
  • 運用: STATS_KEY は Worker の secret。ローカルには cloudflare/aiview-metrics/.stats-key（gitignore）に保管。エンドポイント URL はアプリにコンパイル時定数として埋め込む。

Alternatives considered

  • Sparkle appcast の更新チェック ping で代用 — 自己アップデートまで抱き合わせになり、Homebrew 配布との二重管理が生じる。計測が主目的なので過剰。将来自己更新が欲しくなれば再検討。
  • TelemetryDeck 等の SaaS — 機能は豊富だが外部依存が増える。最小の自前 ping で十分。
  • Cloudflare Analytics Engine — 時系列に強いが、ユニーク install の正確な集計や自前 /stats での取り回しは D1 の方が単純。低トラフィックでは D1 で十分。
  • GitHub download_count のみで運用 — CI/brew ノイズが大きく、起動・継続利用は測れない。却下。
