ADR 001 — favorites.json を v2 ラッパー形式へ拡張

Status: proposed  ·  Plan ref: plan:001

Context

フォルダ毎の状態は <folder>/.aiview/favorites.json に保存されており、現在の形式は ファイル名→お気に入りレベルの素の辞書 [String: Int] である。 今回「最後に表示していた画像」(lastViewedImage) を同じフォルダ単位で永続化したい (ユーザー選択: favorites.json を拡張)。素の辞書のままでは追加メタを同居させられない。

制約: FavoritesStore(actor) は通常モードと統合(サブディレクトリ)モードの両方で このファイルを読み書きする。既存の FavoritesE2ETests と、ユーザーの既存 .aiview/favorites.json 資産を壊さないことが必須。CLAUDE.md の設計思想 「キャッシュ/状態はデータと同じ場所に置く」に従い、保存先は .aiview/ のまま維持する。

Decision

favorites.json をラッパーオブジェクト形式(v2)へ拡張する。 お気に入りは favorites キー配下へ移し、lastViewedImage を同居させる。

// v1 (legacy)         // v2 (new)
{                      {
  "sunset.heic": 3,      "favorites": { "sunset.heic": 3, "draft.png": 5 },
  "draft.png": 5         "lastViewedImage": "draft.png"
}                      }

読込は両形式を構造で自動判別する: まず v2(FavoritesFile)としてデコードを試み、 失敗したら legacy [String: Int] として読み favorites に充てる(lastViewedImage は nil)。 保存は常に v2 で書く ⇒ 旧ファイルは次回保存時に自動マイグレーション。 新フィールドは optional なので前方/後方どちらの読込も壊れない。

flowchart LR
  subgraph Read["読込 loadFile()"]
    R0[Data] --> R1{decode FavoritesFile?}
    R1 -- ok --> R2[favorites + lastViewedImage]
    R1 -- fail --> R3[decode #91;String:Int#93;]
    R3 --> R4[favorites のみ / lastViewed=nil]
  end
  subgraph Write["保存 saveToDisk()"]
    W1[常に FavoritesFile を encode] --> W2[.aiview/favorites.json #40;atomic#41;]
  end

判別の安全性: legacy ファイルにファイル名キー "favorites" があっても、その値は Int なので FavoritesFile.favorites: [String:Int] へのデコードは失敗し legacy 経路へ落ちる。誤判定しない。

Consequences

  • 易: 状態の追加拡張は FavoritesFile に optional フィールドを足すだけ。
  • 易: ユーザー既存資産は無損失で読め、初回保存で透過的に移行。
  • 注意: 統合モードのフォルダ別保存 (saveToDisk(folderURL:favorites:)) は read-modify-write にし、 そのフォルダの既存 lastViewedImage を保ったまま書く(お気に入り編集で前回位置を消さない)。
  • 受容: v2 を書いた後に旧バージョンのアプリで開くと、旧アプリは legacy デコードに失敗し お気に入りを空とみなす可能性がある。個人向けビューアであり前バージョンへの併用は想定しないため許容。

Alternatives considered

  • 別ファイル .aiview/state.json — クリーンだがユーザーは「favorites.json を拡張」を選択。却下。
  • 明示 version フィールドで分岐 — 構造判別で十分かつ legacy には version が無いので、どのみち fallback が要る。冗長なので不採用(将来必要なら追加可)。
