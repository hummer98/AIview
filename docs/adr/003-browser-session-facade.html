ADR 003 — UI facadeとscene-local browser sessionの境界

Status: accepted  ·  Date: 2026-08-11  ·  Finding: ARCH-01 / SCENE-01 / ASYNC-02

Context

従来のImageBrowserViewModelはfolder scan、image load/prefetch、favorite persistence/filter、metadata、slideshow、cache操作、UI transient stateを1 typeで調停し、PR-01〜11後に1,928行へ増加していた。BrowserSessionStateのatomic selectionとsession/generation guardは安全性を上げたが、SwiftUI表示APIとI/O orchestrationの変更面が同じtypeに残っていた。

MainWindowViewも446行で、layoutに加えkey routing、folder importer、alerts/sheet、toolbar、status bar、clipboardを実装していた。行数だけを減らすextension分割では、依存方向とownerは変わらない。

Decision

Type単一の責務所有しないもの
ImageBrowserViewModelSwiftUI向けcomputed snapshot/action facade。互換initializerは依存をcontroller構築に渡す。scanner、favorite store、metadata extractor、filesystem I/O、複製state
BrowserSessionController1 sceneのfolder sessionを調停し、session/load identity一致時だけBrowserSessionStateへcommit。process-global command/state、SwiftUI dialog/layout
BrowserSessionStatephase、URL集合、pending load、BrowserSelectionの純粋でatomicなtransition。I/O、Task、UI
SlideshowControlleractive/paused/interval/settings/timer。tick actionをsessionへ通知。image selection、folder scan
BrowserWindowSessionscene-local Task owner、dialog/zoom/metrics、focused commandの宛先。process-global mutable UI state
 
focused UI event
  -> BrowserWindowSession
  -> ImageBrowserViewModel (facade)
  -> BrowserSessionController
  -> service actor / ImageLoader
  -> BrowserSessionState atomic commit
  -> nested Observation -> SwiftUI

facadeはcontrollerを唯一sourceとしてcomputed forwardingする。facade側にsnapshotをcopyしない。getterがnested @Observable propertyを読むため、controllerの変更はObservation trackingを通じてUIへ伝播する。これはImageBrowserFacadeTestsで直接検証する。

MainWindowViewはscene lifecycle/layout/overlayのcomposition rootに限定し、BrowserKeyboardRouter、BrowserWindowDialogs、BrowserToolbarContent、BrowserStatusBarへ意味単位で委譲する。

Enforcement

scripts/check-architecture.shをtask ciの必須gateとし、facade 800行/MainWindow 350行の上限、facadeのI/O service所有/直接生成、旧global command flag、無効index sentinel、Task.detached、@unchecked Sendable、metadata pathのfull-file read、Swift 5 targetの再導入を検出する。

Consequences

  • 改善: UI contractの変更は292行のfacadeに閉じ、I/Oやsession raceの不変条件はcontroller/stateの既存testを維持したまま抽出できる。
  • 改善: slideshowのsettings/timer所有がselection orchestrationから外れ、SettingsStore()の場当たり的再生成も消える。
  • コスト: 互換APIのforwardingがある。source gateとobservation testで、facadeへ責務/stateが戻ることを防ぐ。
  • 残存課題: BrowserSessionControllerは1,788行で、favorite/filter、metadata coordination、reload/subdirectoryなどsession identityを横断する調停がなお集中する。本ADRはこれを「完全分解済み」とは扱わない。次の分離はsession/load identityを弱めず、独立のbehavior testを伴う場合のみ行う。

Alternatives considered

  • extensionだけで別file化: ownerと依存は変わらず、行数合わせになるため不採用。
  • ViewModelを一度に複数store/controllerへ完全分解: session/generation/selection invariantを跨ぐ変更が大きく、実unit runtimeを起動できないXcode 26.6環境ではリスク過多。段階抽出を選択。
  • facade側にsnapshotを複製: two sources of truthとstale UIを再導入するため不採用。
